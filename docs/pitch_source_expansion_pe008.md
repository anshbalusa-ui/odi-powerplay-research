# PE-008: bounded alternative pre-match source discovery protocol

**Status: proposed for controller review; not frozen.** This document authorizes no search or retrieval. No PE-008 query has been executed and no source-count increase is claimed. Controller approval and a dated, immutable protocol freeze are required before any query execution. This is a retrospective measurement amendment, not fully preregistered: preliminary historical-period modeling has already occurred. It must not be represented as prospective preregistration.

## Purpose and scope

PE-008 proposes one alternative discovery route for registry matches that remain unresolved after the currently frozen source-recovery procedure. It changes discovery only; it does not relax source eligibility, timing, contamination, rights, excerpt review, rubric, consensus, or measurement requirements. The unit is one registry match ID, and the search universe is every registry row whose controller-side PE source status at the frozen cutoff is not `assessable` (including `not_retrieved`, `timing_ambiguous`, `needs_review`, `unavailable`, and `contaminated_or_ambiguous`). Freeze and apply the same status mapping to all rows; do not include already assessable rows solely to increase the source count. Include unresolved matches from every competition, year, publisher, and cohort partition eligible under the registry; never inspect or search for 2025+ match outcomes. Do not use outcome status, pitch labels, historical coder notes/paraphrases, prior assessment, expected category, or source-success likelihood to select, order, repeat, or stop cases.

Before freeze, the controller must create and retain a dated snapshot of the metadata-only unresolved queue and record its SHA-256, exact row count, frozen verified scheduled-start source/hash, protocol hash, search-provider names, and planned execution window. The snapshot may contain only registry identity and search metadata needed below. PE-008 does not assert a current unresolved-row count. Existing collection artifacts can inform eligibility/status only; do not inspect or reuse old pitch codes, notes, excerpts, post-match content, or outcomes for discovery.

## Permitted inputs and query templates

For each unresolved registry row, the only query variables are the frozen `cricsheet_match_id` (or verified match ID if present), match date, both teams, venue/city, and competition/event name. Use their registry spellings, with only deterministic quoting/normalization (trim whitespace, preserve Unicode; no outcome-informed synonyms). Do not add a target category, expected condition, player, toss, score, result, winner, wicket, innings, or post-match wording. Do not query for historical match results or venue performance.

Run exactly these three templates, in this order, for every unresolved row, against each of the two search providers named in the frozen plan (six queries per match; no adaptive reformulation):

1. `"{team_1}" "{team_2}" "{match_date}" "{venue}" preview`
2. `"{team_1}" "{team_2}" "{match_date}" "{event_name}" pitch report`
3. `"{team_1}" "{team_2}" "{match_date}" "{city}" pre-match conditions`

Search execution MUST occur only through a machine-only quarantine gateway, not a human-operated search page or manual browser session. The gateway ingests provider result pages/HTML in an isolated, noninteractive process; raw pages, titles, snippets, URLs and article bodies are never displayed, logged as plaintext, copied, or otherwise made accessible to a human or model collector. It parses the fixed query's results, runs conservative outcome/live/post-match contamination screening over all available result-page text and URL/title fields, and suppresses the whole result-page record on a positive hit, parser uncertainty, or screening error. For a clean result it may release only a positive allowlist: candidate URL, publisher/domain, a title only if independently screened safe, displayed date only if independently screened safe, result rank, and opaque result-page reference. Snippets and surrounding page text are always suppressed. The gateway must retain raw bytes only in restricted, access-controlled quarantine when terms permit, with hash and retrieval metadata; otherwise it must discard them after processing and record only a restricted failure reference. No human may decide whether an unsafe result is followable. If a machine-only gateway with these controls is unavailable or cannot be independently demonstrated to work before freeze, PE-008 remains blocked and no queries may be executed. An empty, suppressed, or contaminated results page is logged by safe reason code and the prescribed remaining queries still run. The controller may suspend the whole batch for a privacy, rights, safety, or service-policy concern; resume only under the same frozen plan or terminate with explicit dispositions, never change query strategy mid-batch.

## Candidate screening and evidence checks

Only the gateway may process provider results or retrieve candidate articles. The gateway must deduplicate and order URLs as below, then fetch only through the approved, rights-compliant verified-TLS workflow. It quarantines complete article bytes and machine-screens metadata and full text for focal-article identity, timing, modification, contamination and excerpt safety. A search-result listing alone is never accepted evidence. No scraping that bypasses access controls, paywalls, robots restrictions, or provider terms. No credentialed or restricted database access without documented authorization. If the gateway cannot confidently screen a page, it suppresses all candidate content and emits only a safe failure reason; no human fallback inspection is allowed.

A candidate can advance only through this staged gateway and independent review of its positively allowlisted output. The gateway's classifier/parser and suppression behavior must be specified, versioned, tested on a frozen set of safe and deliberately contaminated synthetic fixtures, and independently signed off by the controller before queries. This is a readiness condition, not a claim that such a gateway currently exists or has passed validation. If that readiness evidence is absent, do not freeze for execution.

1. **Provider/source identity:** gateway records publisher/provider name, canonical and effective URL, screened-safe title if available, byline and publication identifier only when independently machine-screened safe, original/secondary-source status, and retrieval UTC. Human reviewers receive only safe allowlisted metadata and may confirm publisher attribution from the released provenance; if attribution cannot be established without exposing suppressed material, reject the candidate. The page must be attributable to an identifiable publisher and be an original editorial/reporting source or an authorized syndication whose originating source is traceable. Search engines, aggregators, social posts, user-generated pages, snippets, and unattributed copies are discovery leads, not sources. An official organizer/team/publisher is not automatically exempt from other checks.
2. **Focal-match identity:** the gateway must positively establish the same scheduled ODI by both teams and date, and match venue or competition/round context must disambiguate it using the frozen queue and article content. A series-level general preview, venue-only description, another fixture, or ambiguous double-header does not qualify. It releases only the required match-identity evidence in safe, minimal paraphrase; if identity evidence contains an outcome cue or cannot be safely minimized, suppress the candidate. Do not resolve ambiguity using outcomes or historical coder notes.
3. **Pre-start timing:** gateway independently verifies precise publication time and timezone from publisher metadata or contemporaneous publisher record and compares it with the frozen verified scheduled start. Publication must be strictly before start. Date-only evidence is insufficient if it cannot establish strict pre-start ordering. It releases only the timestamp, UTC conversion and safe provenance locator; suppress raw metadata/page text. Current access/retrieval time is not publication time.
4. **Content integrity / temporal boundary:** gateway requires publisher last-modified time strictly before scheduled start when available and no contradictory later modification evidence. If the live page has no trustworthy modification boundary or may have been amended, it is ineligible unless an exact-URL Internet Archive replay independently satisfies the existing PE-006 requirements: verified original URL, successful replay, capture strictly after publication and before start, exact replay URL/timestamp, immutable local snapshot and SHA-256, and no embedded modification after capture or start. An archive index hit or search cache is not a source. Do not broaden archive lookup beyond the explicitly frozen PE-006 rule.
5. **Contamination and safe evidence:** gateway processes the complete article in quarantine and screens for live coverage, scorecards, toss/result/winner/final-score/innings outcome, post-match or later observed-condition material, mixed temporal versions, and unresolved contamination before any reviewer sees content. On any positive hit, uncertainty, parse failure or uncertain separation, suppress the entire candidate: raw article, metadata/title that may signal outcome, and excerpt never reach a person or assessor. For a clean page only, the gateway releases a minimum short, article-scoped pre-match condition excerpt and its hash, with unsafe adjacent/embedded material excluded. A second reviewer independently confirms focal relevance, timing, absence of contamination, and excerpt fidelity using only the allowlisted packet; any unresolved concern rejects it. No manual raw-page inspection or human triage of quarantined material is permitted.
6. **Rights and retention:** gateway records rights/access restrictions, terms consulted, permitted local processing/retention, and whether the proposed short excerpt is permissible. Respect copyright, access controls, publisher terms, archive terms, privacy, and takedown requests. Keep raw snapshots only in the approved ignored/quarantined location with restricted access and immutable hashes; never commit raw copyrighted pages. Persist only permitted provenance and a minimal independently approved excerpt/paraphrase in the assessor-input path. Rights uncertainty means do not retain or use the source; record `rights_unresolved`.

No old coder paraphrase, historic pitch code, previously screened excerpt, old assessment, or search snippet may substitute for a PE-008 original-source capture or reviewer decision. Do not inspect outcome-bearing materials to adjudicate any check.

## Deduplication, limits, and stopping

The gateway deduplicates raw URLs in quarantine using normalized canonical URL (lowercase host, remove fragment and known tracking parameters, normalize default ports; preserve path/query parameters that identify content). It also machine-flags same publisher/article ID or exact title/byline/publication-time matches at different URLs for duplicate adjudication. If duplicate identity cannot be resolved using screened-safe metadata, suppress the candidate rather than expose unsafe details for human adjudication. Keep one source record per distinct underlying article; multiple mirrors/syndications of one article do not count as independent sources. Record all query/provider/rank discovery paths against an opaque candidate ID. A later copy cannot replace a rejected source unless it is demonstrably a distinct original article and all six screening checks are repeated.

Hard cap: six metadata-only queries per unresolved match, two named search providers, three fixed templates, one complete pass, and at most the first ten unique candidate URLs per match in the deterministic merged result ordering. The gateway applies this cap to candidates internally; it exposes only positively allowlisted, screened-safe records. Do not extend the cap because a match has few candidates, a candidate looks promising, or a partition has low coverage. Do not stop early on finding an eligible source: complete all six prescribed queries and gateway screening up to the cap for every match, so yield does not affect effort. No query reruns, provider swaps, follow-on searches, link-chain exploration, or new discovery mechanisms. A provider outage is logged by safe reason code; after one retry of the same prescribed query at the next scheduled service window, record remaining query opportunities as `search_provider_unavailable` and continue the fixed plan with the other provider. No third provider or changed wording is permitted. At cap/exhaustion, freeze the per-match disposition; no ad hoc exceptions.

Every unresolved match receives exactly one terminal disposition:

- `eligible_source_reviewed` — at least one distinct candidate passes all checks and the excerpt receives independent approval;
- `no_candidate_found` — completed fixed queries yield no candidate URL;
- `candidate_not_match_specific` — candidates exist but none establishes focal-match identity;
- `publication_time_unverifiable` — focal candidate exists but strict pre-start publication cannot be established;
- `amended_or_temporally_ambiguous` — no candidate passes the content-integrity boundary;
- `contaminated_or_unsafe_excerpt` — all relevant candidates are contaminated or cannot yield safe excerpts;
- `rights_unresolved` — no otherwise qualifying candidate has documented permissible processing/retention;
- `inaccessible_or_provider_unavailable` — access fails or query service failure prevents evaluation;
- `duplicate_only` — candidates resolve only to an already counted underlying article, with no distinct eligible source.

Where several failure reasons apply, assign the earliest failed check in the screening sequence and retain secondary reasons in the controller manifest. `eligible_source_reviewed` is a measurement-eligibility disposition, not proof of pitch accuracy or a claim of increased source count.

## Required audit record and precommit gate

Before any assessor run, publish a controller-only, immutable manifest binding: protocol and queue snapshot hashes; exact row count; gateway code/config/classifier versions, readiness-test evidence and hashes, independent sign-off; query templates, providers, rendered-query hashes/logs, UTC times, opaque result-page/candidate references, candidate ordering and deduplication decisions; each candidate's safe source/provider identity, allowlisted URL/title fields only when passed screening, match-identity evidence, publication/modification/capture evidence, timing comparison, contamination and excerpt decisions, rights/retention decision, reviewer identities, permitted excerpt hash, and reason codes; per-match terminal disposition; and any missing query caused by outage. Raw URLs, result pages, titles, snippets, article text, outcomes, historical labels/notes, and unsafe excerpts must never enter a human-readable manifest; retain raw material only in access-controlled machine quarantine when rights permit, with hash and retrieval metadata. If safe provenance cannot be recorded without disclosure, store an opaque reference and reject the candidate for release.

A controller independent of discovery must verify the frozen queue was processed uniformly, all dispositions and provenance are complete, rights are resolved for included sources, excerpt reviews passed, no locked outcome data were accessed, and the positive assessor payload contains only the established permitted metadata plus independently approved safe excerpts. Any failed gate blocks measurement. Freeze the complete changed release and its hashes before scoring. Because its source set/input hash changes, discard/supersede all prior A/B/C assessments for the affected release and run all three fresh independent passes A/B/C over the same complete newly hashed release using the exact frozen rubric and unchanged assessment schema. Record each pass's provider-observed response model ID verbatim; a requested route, CLI label, version, or alias without provider-observed identity does not satisfy PE-007. Pause if any pass lacks that observed identifier. Do not selectively rerun rows or reuse previous passes. This source expansion does not authorize pitch-outcome analysis; human approval and all existing downstream gates remain required.

## Decision and claim boundary

Controller review must approve or reject this proposal and, if approved, freeze its exact content and execution parameters before any search begins. Any change to query wording/providers, queue, limits, eligibility, source timing, contamination, rights, or deduplication after freeze requires a new protocol version and a new freeze before queries; affected screening is invalidated and the full changed release requires fresh A/B/C passes. No outcome-informed amendment is allowed. Report actual query and disposition counts only after execution, with denominator and protocol version, and never imply that more sources were found unless observed counts establish that result. Preserve the retrospective observational claim boundary; PE-008 supplies no estimates, outcome evidence, causal claim, or assertion of improved coverage.
